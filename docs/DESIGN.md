## Navigation

The main window starts centered on screen at `1360 × 860 pt` (`MinWidth: 960`, `MinHeight: 680`, freely resizable and maximizable) and uses a continuous `44 pt` top chrome strip (`TitleBarHiddenInset` with `TrafficLightPosition {16, 14}`) so the macOS traffic lights align on the exact horizontal centerline with three fixed navigation buttons separated by a `20 pt` safety gap: **Toggle sidebar** (`⌘B`), followed by a `10 pt` gap and the **Go back** (`⌘[`) / **Go forward** (`⌘]`) pair. Below the top strip sit the `200 pt` sidebar (`56 pt` icon rail when collapsed) and the seamless rounded top-left (`12 pt`) main content canvas. Back and Forward traverse the session's navigation history across Problems and opened Workspace problems, saving dirty drafts before switching.

Navigation opens with a transparent brand workspace header (`30 × 30 pt` multi-color LeetCode emblem rendered via `ui.Icon` from embedded light/dark SVGs in its native amber/charcoal/grey colors with no background fill, `12 pt` gap before bold `14 pt` `LeetCode` / `LeetCode CN` title and `leetcode.com` / `leetcode.cn` domain, animated `0° ↔ 180°` chevron on the right when switchable, or a `5 pt` live status dot with soft halo inline (`12 pt` gap) beside the site title when signed in; `26 × 26 pt` emblem when collapsed) separated by a visible sidebar-tuned inset hairline (`#d8dae3` Light / `#252730` Dark) above `Problems`. Site switching is enabled only on the Problems screen while signed out; in Workspace or while signed in, the brand header stays read-only with an explanatory tooltip. All sidebar rows share a unified `10 pt` horizontal inset, `22 pt` centered icon/avatar slot, and `10 pt` label gap so icons, user avatars, and labels align along one vertical axis. Interactive controls apply snappy micro-press scaling and smooth `130 ms` color transitions. Below `Problems` sit a dedicated `Current problem` section when a problem is open and a separate `Recent` section showing up to 5 other recently opened problems during the session for one-click switching. The sidebar's expanded/collapsed state is global across all screens and never changes during page transitions, Go back, or Go forward. Selecting the open problem resumes the active editor. Account and Settings sit at the bottom. `⌘P` / `⌘K` (or `Ctrl+P` / `Ctrl+K`) opens Quick Open. `⌘,` (or `Ctrl+,`) opens the independent Settings window centered over the main window; Settings remains open while interacting with the main window, brings the main window directly beneath it when re-activated from another application, and closes via `Esc`, `⌘W` / `Ctrl+W`, or the window close button.

The guest account entry opens a borderless-chrome sign-in dialog (`480 × 308 pt`, hidden titlebar and hidden window buttons, centered over its parent window with screen-center fallback, freely draggable across non-button surfaces, dismissible with `Esc` or `⌘W` / `Ctrl+W`). LeetCode and LeetCode CN occupy equal-width cards on one row with radio indicators, selected accent tint, and a privacy note below. Selecting a card changes the pending login site. Continue opens a dedicated `980 × 760 pt` (`MinWidth: 780`, `MinHeight: 620`) draggable full-bleed window centered over the main window (with screen-center fallback) hosting the official login page in an isolated WebView (without a permanent bottom bar), displaying a native loading state until DOM ready and a retry state on load failure; Declic automatically verifies the session cookies on navigation and periodic checks, completing sign-in and closing the window automatically (showing a compact fallback error bar only on failure). Cancel leaves the active site, identity, and editor intact.

When signed in, Declic enriches the verified viewer with public profile data (`matchedUser` on `leetcode.com` and `userProfilePublicProfile` on `leetcode.cn`) to load the viewer's normalized HTTPS avatar (falling back to an initial circle) and real name/nickname. The sidebar account row shows a `20 pt` circular avatar and display name. The signed-in account popover (`180 pt` wide, aligned flush with the sidebar) displays a compact `32 pt` avatar, `13 pt` bold nickname, a muted `11 pt` site caption, a hairline divider, `Open profile` with external icon, `Sign in again` when expired, and `Sign out` with danger hover styling.

## Problems

The Problems surface centers its content in a `1040 pt` max-width container (`22 pt` top, `32 pt` horizontal padding) with `16 pt` separation between the Daily Challenge card and the problem catalog controls, and `14 pt` between the toolbar and table header when no filter chips are active (`8 pt` when chips are shown).

The daily challenge card (`14 pt` radius, `18 × 22 pt` padding, always expanded, directly clickable to enter Workspace) omits reset countdown and site-badge noise and pairs a compact top meta row (calendar icon, `Daily Challenge · <Date>`) above a two-column body:
- Left column: bold `18 pt` problem title with inline solved checkmark circle, followed by the difficulty pill and all topic chips rendered with crisp white/bordered contrast (`#ffffff` + `#d8e1f5` border in Light; `#1c263a` + `#2d3f60` border in Dark) wrapping cleanly without `+N` truncation.
- Right middle-bottom: lightweight `Solve →` (or `Review →` when solved) accent affordance (or `Retry` button on error).

Catalog controls sit on one `38 pt`-tall toolbar row:
- **Search**: flexible search input with leading search icon, inline muted total count and loading/updating indicator when no filters are active (avoiding layout jumps during catalog refreshes), and `⌘F` badge.
- **Difficulty**: single-select segmented control (`All` / `Easy` / `Medium` / `Hard`; clicking the active difficulty toggles back to `All`).
- **Sort (icon-only, hover `"Sort"`)**: opens a sort popover for `ID`, `Title`, `Acceptance`, and `Difficulty` (matching unified `12 pt` semibold muted section headers across Sort and Filters popovers), synchronized with clicking the corresponding table column headers (`#`, `Title`, `Acceptance`, `Difficulty`). Problem titles are trimmed of stray leading/trailing whitespace on load and during sorting.
- **Filters (icon-only, hover `"Filters"`, accent count when active)**: opens the filter popover grouping single-select `Status` (`All` / `Unsolved` / `Solved`), single-select `Access` (`All` / `Free` / `Premium`), and multi-select searchable `Topics` with per-topic counts and a `Reset` action.
- **Pick one (icon-only shuffle arrows, hover `"Pick one"`)**: opens a random matching problem respecting the viewer's known Premium entitlement.

Active Status, Access, and Topic filters appear directly below the toolbar as removable accent-tinted chips with a `Clear` link alongside the right-aligned total problem count; when no filters are active, that row stays hidden so the toolbar sits cleanly above the table header without jumping during background refreshes.

The problem table hides default scrollbars, uses a symmetrically inset bottom hairline (`10 pt` horizontal padding on both sides matching the row corner radius) under the `36 pt` column header row (no dividers between problem rows), snaps its scroll viewport height to an exact integer multiple of the active row step (`48 pt` Comfortable / `38 pt` Compact) across window resizes, and overlays smooth `PassThrough` top/bottom surface fade gradients while mid-scroll so rows entering or leaving the viewport dissolve cleanly instead of clipping abruptly. When signed out, no status column is reserved; when signed in, a centered `32 pt` solved indicator column sits cleanly indented on the left. `#` (`48 pt`) is centered with an `8 pt` gap before sortable `Title` (with inline purple `Premium` / `会员` lock pill), followed by centered `Acceptance` (`92 pt`) and centered `Difficulty` (`84 pt`) flush with the hairline's right edge. Rows (`46 pt` Comfortable / `36 pt` Compact, `10 pt` radius) highlight on pointer hover or keyboard `↑` / `↓` navigation (keyboard navigation stays active even when the pointer rests over a row and hands back cleanly on pointer movement), and support `Enter` to open. Clicking an unentitled Premium problem opens a centered modal dialog explaining subscription requirements with `Open on <site>` and `Sign in` (for guests) actions. Centered pagination (`72 pt` footer with generous top breathing room and no top divider) displays `Previous` and `Next` in matching accent color when enabled, numbered pages with ellipsis (`1 2 3 … N`), and an accent-filled active page button, and hides automatically when results fit on a single page.

The first page can appear while the full public catalog is loading. The app stores the public index separately per site, reuses a fresh index for 24 hours, and silently prefetches the public daily challenge detail into cache. Search, filters and sort operate before pagination. Quick Open uses the same index and also matches slugs. Catalog position survives a visit to Workspace.

## Workspace

Workspace occupies one unified `Surface` panel separated internally by `1 pt` hairline dividers (vertical split between Problem and Editor, horizontal split between Editor and Test Panel), hiding default scrollbars across panels and the description WebView. Both splits support dragging; windows narrower than `1050 pt` switch between Description and Editor tabs.

The left pane contains `Description`, `Editorial` (`leetcode.com` only; `leetcode.cn` omits the legacy `Editorial` tab because official editorials live inside `Solutions`, matching the official site), `Solutions`, and `Submissions` in a `44 pt` tab bar with leading semantic icons and a `2 pt` accent underline on the active tab:

- **Description**: `22 pt` bold title with a vertically centered external-link icon button (`30 × 30 pt`, `12 pt` gap) immediately after the title, difficulty and topic pills, CN bilingual toggle (`中文 / EN`), followed by an isolated WebView rendering sanitized HTML in an ephemeral session. Sanitization removes empty spacer paragraphs/divs (`<p>&nbsp;</p>`), collapses consecutive `<br>` and excessive blank lines (at most one blank line), converts inline and display LaTeX (`$...$`, `$$...$$`, `\(...\)`, `\[...\]`) into native Presentation MathML styled with serif math typography directly on the page background (no background card), and applies clear proportional heading typography (`h1` / `h2` / `h3` / `h4` plus bold section labels such as `Example 1:` and `Constraints:`). Code/example blocks use uniform `10 pt` rounded inset boxes with a subtle `1 pt` outline (no left accent stripe); images and graphs receive a light backing frame in Dark mode for legibility; trusted video embeds (`<iframe>` and `<video>`) render as safe clickable walkthrough cards; multi-heading descriptions generate a collapsible `Contents` TOC. Multiple hints render as separate ordered disclosures (`Hint 1`, `Hint 2`, …) with leading lightbulb icons and right-aligned chevrons (omitted when none exist). `Similar Questions` uses a leading branch icon and right-aligned chevron, resolves Question IDs from the site catalog, and lists `#ID · Title`, optional `Premium` / `会员` badge, and `Difficulty` pill; clicking a row intercepts a local `https://declic.local/problem/<slug>` route to open that problem in Workspace after saving any pending draft.
- **Editorial**: retains the problem header (Question ID, title with external link, Difficulty, and Topics) above a preprocessed native Markdown reader (`parser.Default | parser.ExtDollarMath`). Literal `[TOC]` markers and empty HTML spacers are stripped; multi-heading articles show a collapsible native `Contents` TOC. Rich media and text render natively:
  - **Video Solution**: `<iframe>` embeds (Vimeo, YouTube, Bilibili, Wistia, Loom, Tencent/Youku, Mux), HTML5 `<video>` / `<source>` tags, linked video thumbnails (`[![alt](thumb)](videoURL)` / `<a><img></a>`), and `leetcode.cn` UUID video embeds (`![*.mp4](<uuid>)` resolved via `videosVideoInfo` into a native `16:9` HD cover card that plays in an isolated Aliplayer WebView on click, or a members-only lock card when `canSee` is false) render **directly as a pure `16:9` inline player** inside the main page (`12 pt` rounded corners, dark `#0c0e12` backdrop, provider `preconnect` hints, shimmer + spinner loading overlay, with no footer bar or letterbox padding) backed by a shared isolated ephemeral session (`mygo.NewEphemeralSession()`, `Untrusted: true`, strictly separated from login cookies while caching player assets in memory). Empty/Premium-only `Video Solution` sections with no accessible video are omitted cleanly from the article and TOC. Editorial videos pre-warm in the background as soon as the prefetched article arrives; switching between `Description`, `Editorial`, `Solutions`, and `‹ All solutions` within the same problem pauses and mutes playback while keeping players alive for instant re-entry, and players are destroyed automatically when switching problems, sites, or closing the window.
  - **Linked & inline images**: non-video linked images (`[![alt](img)](link)`) and inline images mixed with text render as full clickable images rather than raw `[alt]` text.
  - **Interactive walkthrough slides**: LeetCode `!?!...json!?!` slide specs resolve and fetch the public manifest JSON and frame images off-thread (with ±1 frame prefetching), rendering a native `Step X / N` slideshow card (`Prev` / `Next` controls, dark-mode light frame backing, and external fallback).
  - **Implementation & multi-language code tabs**: LeetCode UGC articles with literal `\n` / `\t` escapes are automatically unescaped (preserving escaped newlines inside code strings and LaTeX commands), trailing `[]` fence markers (such as ```` ```java [] ````) are normalized for syntax highlighting, embedded LeetCode Playground iframes fetch public snippets via `allPlaygroundCodes`, and consecutive fenced code blocks in 2+ distinct programming languages automatically merge into the same native multi-language tabbed code card (preferring the active editor language, with syntax highlighting and built-in Copy button).
  - **Math & LaTeX**: styled to match LeetCode's official KaTeX typography with **no background box** — inline TeX (`$...$`, `\(...\)`, including digit-started formulas such as `$0$` and `$1 \le n \le 10^4$`) renders via `markdown.Options.InlineMath` using unified `Times New Roman` serif `TextLayout` runs (italic variables, upright digits, brackets, and operators, baseline-aligned, copying as original TeX), while display math blocks (`$$...$$`, `\[...\]`) render centered directly on the page background in serif math font with stacked fractions, stacked `∑`/`∏`/`lim` bounds, `\begin{array}`/`\begin{cases}`, and scaled curly braces.
  - **Mermaid diagrams**: `mermaid` fenced blocks (`flowchart` / `graph`, `sequenceDiagram`, `stateDiagram`) render natively on GPU canvas with a `Diagram` / `Source` toggle and `Copy` button (with graceful source fallback for unsupported diagram kinds).
  Shows a contextual `Null` empty state (`"No official editorial yet"`) when unavailable.
- **Solutions**: retains the problem header (Question ID, title, Difficulty, and Topics) above a persistent lightweight `44 pt` filter toolbar (left-aligned compact `Hot` / `Newest` / `Most votes` sort pills and right-aligned toggleable language chip with code icon, separated by a bottom hairline, remaining mounted without page-level flicker while loading new filter results) and structured solution rows separated by inset hairline dividers, each pairing a full-width title above icon-backed metadata (user icon + author, upvote icon + count, eye icon + views) and a right disclosure chevron without placeholder avatars. Scrolling near the bottom automatically lazy-loads the next page in place (keeping existing rows and scroll position intact with an inline `"Loading more…"` footer and a fallback `"Load more"` link). Solution articles share the same cleaned Markdown, TOC, direct inline video player, interactive slides, auto-merged multi-language code tabs, math/LaTeX, Mermaid diagrams, and Playground snippet rendering. Empty views show contextual copy (`"No matching solutions"` or `"No community solutions yet"`).
- **Submissions**: requires a verified session; when signed out or expired, displays a vertically and horizontally centered empty state with icon badge, explanation, and primary `Sign in` / `Sign in again` button. Signed-in view includes interactive `Status` and `Language` filter dropdown headers above `Runtime`, `Memory`, and `Submitted` columns (`42 pt` rows, contextual `Null` empty state `"No submissions yet"` / `"No matching submissions"` instead of generic `"No data"`), and opens a detail view with `‹ All submissions`, verdict header, syntax-highlighted code block with built-in copy button, and a bottom-right `Use this code` button (with undo-checkpoint tooltip and brief `Loaded` confirmation). Loading a submission into a different language saves the current draft first.

The right pane stacks the code editor and a separate test panel separated by a `1 pt` horizontal divider:

- **Editor**: `44 pt` header with a wider language selector pill (`138 pt` min width, leading code icon, language label, vertically centered chevron) opening a multi-column popover supporting all LeetCode languages (up to 3 columns with vertical dividers and active checkmark), plus right-side icon controls ordered from left to right as **Format code** (left-aligned varying-length bars, available whenever code is non-empty so official templates can be reformatted to preferred tab width), **Copy code**, **Retrieve last submitted code** (clean `{ }` braces, disabled while signed out), **Reset template** (open counterclockwise arc, disabled when code matches the official template), a vertical divider, **Quick settings** (inline popover for font size, tab width, word wrap, and auto-close brackets, synced with `Settings > Editor`), and **Focus editor** (`⌘\`, maximizing the editor/test pane to full workspace width); opening a new problem remembers and prefers the user's last-used language when supported. The native `editor.View` body matches `Surface` with `NoScrollPastEnd` enabled, `SoftWrap` enabled by default, and configurable font size (`11–18 pt`), tab width (`Auto` using language-conventional indentation via `editor.IndentAuto`, or manual `2` / `4 spaces`), and auto-close brackets. The `54 pt` footer holds `Ln X, Col Y`, save-retry link on failure, outlined `Run` button (`⌘↩`), and primary `Submit` button (`⌘⇧↩`), both disabled while the editor is empty or unchanged from the official template.
- **Test panel**: `44 pt` header with pill-style `Testcase` and `Test Result` tabs, collapsed case count (`N cases`), and chevron toggle (`⌘J`). `Testcase` presents wrapping accent-tinted case chips (`Case 1`, `Case 2 •`) where hovering or explicitly clicking a chip reveals a small top-right circular `×` delete badge (hidden by default on load and when only one case exists), followed by `+` and a normal always-clickable `Reset` icon button (accented when cases are edited), above stacked parameter labels and inset input fields. `Test Result` displays granular execution stages (`Verifying session…` → `Running testcases…` / `Submitting code…` → `Judging…`), Run status with inline runtime, selectable pass/fail case chips, and `Input` above a two-column `Output` / `Expected` comparison with character-level diff highlighting on mismatch (danger tint on `Output`, success tint on `Expected`), collapsible previews for long outputs (`Show all` / `Collapse`), and one-click `Copy` icons per field; Submit results show verdict, passed/total count and language, `Add to testcases` on failure, two-column `Runtime` / `Memory` metric cards with percentile beats on acceptance, and immediate in-memory solved status refresh upon `Accepted`.

Public non-paid problem details and public editorials use a dual-layer memory + per-site disk cache (7-day TTL), while Premium content and private submissions stay strictly in memory. Clicking a catalog problem enters Workspace immediately with known metadata while uncached details load off-thread, and verified sessions are reused in memory for 5 minutes (invalidated immediately on sign-out or auth errors). Public editorials prefetch silently after a problem opens.

Run and Submit take code snapshots and verify the site's viewer before sending code. A timed-out or interrupted request can leave the result unknown. Stop waiting cancels local polling. A successful server response supplies verdicts, outputs, errors and metrics. Submissions never repeat automatically.

## Appearance and data

The independent Settings window (`780 × 540 pt`, `MinWidth: 620`, `MinHeight: 400`, centered over the main window on open, draggable and resizable, dismissible with `Esc` or `⌘W` / `Ctrl+W`) uses a `196 pt` left category sidebar (`#f2f3f7` in Light, `#131417` in Dark) with left-aligned categories ordered as `General`, `Appearance`, `Problems`, `Workspace`, `Editor`, `Run & Submit`, `Shortcuts`, `Account & Network`, and `Storage`, paired with a `Surface` content pane of `54 pt` minimum-height rows (label and muted description on the left, right-aligned control). `General` exposes the browsing site selector (`leetcode.com` / `leetcode.cn`, disabled while signed in), `Open on launch` (`Problems` / `Last workspace`), and `Restore session on launch` (`On` / `Off`); `Appearance` exposes `Theme` (`System` / `Light` / `Dark` segmented control, synced to native window chrome via `mygo.Theme.SetSource`), `Dock icon` on macOS (radio group offering `Default` — restoring the bundle's appearance-aware `AppIcon.icon` — plus built-in alternate Dock icons applied while running via `mygo.App.Dock.SetIcon`), `Contrast` slider, `Density` (`Compact` / `Comfortable` segmented control), `Description font size` (`−` / `15 pt` / `+` stepper from `13 pt` to `19 pt`), and `Show topic tags` (`On` / `Off` segmented control); `Problems` exposes `Acceptance column`, `Difficulty column`, `Hide Premium problems`, and `Problems per page` (`20` / `50` / `100`); `Editor` exposes `Font size` (`11–18 pt`), `Tab width` (`Auto` / `2 spaces` / `4 spaces`), `Wrap long lines`, and `Auto-close brackets` alongside read-only autosave/initialization notes; `Account & Network` handles sign-in and sign-out; `Storage` shows live local draft count/size with `Show in Finder` (`Open folder` on non-macOS) and public cache size with `Clear caches` (strictly removing `<user-data>/cache/` without touching drafts); `Workspace`, `Run & Submit`, and `Shortcuts` surface key bindings and runtime notes.

Settings, preferred language, and split preferences persist via debounced atomic saves during the session (with a final flush at normal shutdown); the main window re-opens centered at its default `1360 × 860 pt` size on launch. Private submissions, Premium details, and solve flags stay in memory (with paid details purged on sign-out, expiry, or site switch). Existing account-scoped drafts and legacy library files retain their original paths. Opening a problem no longer records a local visit.

## Verification scope

Offline tests exercise top navigation ordering and `⌘B` / back-forward history, sidebar panel placement, login selection and loading/error states, single-select difficulty, Title sorting, keyboard list navigation, access filters, catalog pagination, quick open, expanded language extensions, code formatting, HTML/MathML/Markdown/TOC/video rendering, public detail cache isolation (never persisting paid problems), Premium modal gating, submissions status/language filtering, testcase editing, separate hints and clickable similar-question routing, judge error/session-invalidation notices, macOS Dock icon assets/picker/restore, settings appearance controls, editor preservation, save failure, and identity boundaries. Live guest checks cover catalog, challenge, description, and public articles on both sites. Authenticated judging, account history, and Premium access require an account for end-to-end verification.
